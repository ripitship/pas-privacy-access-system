## FAQ

What is the purpose of this repository? It presents Leo de Matos's personal development project for constructive feedback on the idea, architecture, integration and security boundaries. It is not a commercial offer. Future collaboration can be discussed separately if interest develops.

Is PAS free open source? No. The PAS source remains private under the existing proprietary software restrictions. Private technical evaluation requires individual approval and agreed terms. Public documentation is not permission to use the PAS software.

Does no mandatory email mean anonymous or legally cleared? No. Operators must assess identity, privacy and legal obligations in context. No complete anonymity or compliance certification is claimed.

Can I contact the initiator through GitHub? Use Issues for ordinary, non-confidential questions and feedback when you have repository access. In a public repository these posts are public. GitHub has no general private-message inbox. Sensitive findings require the configured private reporting or explicitly granted review channel described in SECURITY.md. Security reporting is not a private mailbox for general business or personal conversations.

Do I need an email to use PAS or give feedback? Mandatory email is not part of the PAS access model. GitHub participation uses a separate GitHub account; GitHub's own account requirements are not PAS requirements. No separate public project email is currently provided. This contact choice does not establish an exemption from applicable provider or legal duties.

Does asking for code grant access? No. Individual approval, terms, hosting choice and minimum necessary access precede disclosure. There is no response SLA.

Can I run this documentation repository? It contains documentation and a Python standard-library documentation checker, not PAS software or an executable demo.

## Roadmap

Near-term goals: constructive developer/security feedback, focused individually approved integration reviews, explicit operator evidence and threat-model assessment. Production gates include independent security/SCA review, rights/contact assessment, actual browser/authenticator coverage, isolated key/witness custody, restore/HA and deployment evidence. P2 stays blocked. This is a development roadmap, not a product availability, sales or support commitment.
