# Sensitive findings / Sensible Befunde

Status 2026-10-26: GitHub private vulnerability reporting is enabled for this public documentation repository. The public **Report a vulnerability** entry was verified while signed out. No test report was submitted; message delivery, response time or continuous monitoring has not been demonstrated or promised. A GitHub sign-in is required to submit a report.

Stand 26.10.2026: Private Schwachstellenmeldung über GitHub ist für dieses öffentliche Dokumentationsrepository aktiviert. Der öffentliche Einstieg **Report a vulnerability** wurde ohne Anmeldung geprüft. Keine Testmeldung wurde abgeschickt; Zustellung, Reaktionszeit oder laufende Überwachung werden damit nicht belegt oder zugesagt. Zum Einreichen einer Meldung ist eine GitHub-Anmeldung erforderlich.

Do not post vulnerabilities, exploit proofs, secrets, private state, personal data or customer details in public issues, discussions or pull requests. For a confidential security finding about the PAS material or an individually approved evaluation, use **Security and quality → Advisories → Report a vulnerability** if GitHub displays that action for this public repository. GitHub private vulnerability reporting must actually be enabled; this file alone does not activate or prove the reporting service. If the action is unavailable, ask in an issue for a confidential security contact without describing the finding, and wait for an explicitly approved private channel. Never publish sensitive details as a workaround. Private vulnerability reporting is for security findings, not general business or personal messages. No response time, bounty, ongoing monitoring or customer support is promised. This personal development project's documentation is not a production-supported software release.

Keine Schwachstellen, Exploit-Nachweise, Geheimnisse, privaten Zustände, personenbezogenen Daten oder Kundendetails in öffentliche Issues, Diskussionen oder Pull Requests stellen. Für einen vertraulichen Sicherheitsbefund zu den PAS-Unterlagen oder einer individuell freigegebenen Evaluation **Security and quality → Advisories → Report a vulnerability** verwenden, sofern GitHub diese Aktion für das öffentliche Repository anzeigt. Private Schwachstellenmeldung muss tatsächlich aktiviert sein; diese Datei allein aktiviert oder belegt keinen Meldedienst. Fehlt die Aktion, in einem Issue ohne Beschreibung des Befunds nach einem vertraulichen Sicherheitskontakt fragen und auf einen ausdrücklich freigegebenen privaten Kanal warten. Sensible Details niemals ersatzweise veröffentlichen. Private Schwachstellenmeldung dient Sicherheitsbefunden, nicht allgemeinen geschäftlichen oder persönlichen Nachrichten. Keine Reaktionszeit, Prämie, laufende Überwachung oder Kundenbetreuung wird zugesagt. Die Dokumentation dieses persönlichen Entwicklungsprojekts ist keine produktionsunterstützte Softwareveröffentlichung.
